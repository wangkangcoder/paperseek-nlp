# PaperSeek 回退机制说明

> 目标：任何一次修改造成的问题都能在 1~2 条命令内恢复到已知良好状态（SRS 风险控制“数据/索引版本漂移”）。
> 工具：`tools/rollback.py`（跨平台 Python 实现，不依赖 PowerShell 7）。
> 备份目录：`backups/`（已 gitignore）　快照清单：`backups/snapshot-*.zip`

## 1. 五层回退体系

| 层级 | 机制 | 恢复粒度 | 适用场景 |
| --- | --- | --- | --- |
| L1 | 细粒度 git commit（每个功能/修复一次） | 单个提交 | 改错一个函数、回看某次实现 |
| L2 | annotated tag（每个里程碑/版本） | 里程碑 | 实验做坏了，回到“指标可信”的版本 |
| L3 | 文件级快照 `tools/rollback.py snapshot` | 工作区全部源码（含未提交改动） | 大规模重构前、危险实验前 |
| L4 | 回退前自动备份分支 `backup/pre-rollback-<时间>` | 回退前状态 | 回退后发现“原来那版更好” |
| L5 | GitHub 远端 `origin/main` + tags | 异地/灾难恢复 | 本地仓库损坏、换机器 |

**提交门禁**：`tools/rollback.py checkpoint` 会先跑 pytest（可选），测试不过拒绝提交，避免把坏状态写进历史。
**忽略策略**：`.venv/`、`data/raw|index|local_pdfs/`、`logs/`、`backups/`、`__pycache__` 不入库，
因此快照与仓库不会包含大文件；数据/索引通过脚本重建（`download_data.py` + `build_index.py`）。

## 2. 常用命令（项目根目录执行）

```powershell
# 查看当前状态：分支、HEAD、tag、工作区是否干净
.\.venv\Scripts\python.exe tools\rollback.py status

# 列出里程碑 tag 与快照
.\.venv\Scripts\python.exe tools\rollback.py list
.\.venv\Scripts\python.exe tools\rollback.py snapshots

# 危险操作前拍文件级快照（含未提交改动）
.\.venv\Scripts\python.exe tools\rollback.py snapshot -m "重构前快照"

# 提交检查点：先跑测试 → git add/commit →（可选）打 tag
.\.venv\Scripts\python.exe tools\rollback.py checkpoint -m "feat(retrieval): 完成 BM25 [CHG-010]" --tag v0.2.0-w2 --test

# 回退到某个 tag/提交（自动先建 backup 分支 + 文件快照，然后 hard reset）
.\.venv\Scripts\python.exe tools\rollback.py restore v0.2.0-w2 --yes

# 撤销上一次 restore：回到回退前状态
.\.venv\Scripts\python.exe tools\rollback.py undo

# 只看 diff，不改动
.\.venv\Scripts\python.exe tools\rollback.py diff v0.2.0-w2
```

## 3. 典型回退剧本

### 场景 A：某次实验代码改坏，指标异常
```powershell
python tools\rollback.py status                    # 确认工作区有未提交改动
python tools\rollback.py snapshot -m "异常前"       # 先把现状存一份
python tools\rollback.py restore v0.3.0-w3 --yes   # 回到已验证里程碑
# 分析差异后重新实现，必要时 undo 回来对比
```

### 场景 B：只想回退单个文件
```powershell
git checkout v0.3.0-w3 -- src/paperseek/retrievers/sbert.py
```

### 场景 C：本地仓库损坏 / 换电脑
```powershell
git clone https://github.com/wangkangcoder/paperseek-nlp.git
git tag -l                        # 确认里程碑
python tools\setup_env.ps1        # 重建环境（CHG-001）
python scripts\download_data.py   # 重建数据
python scripts\build_index.py     # 重建索引
```

### 场景 D：索引与语料版本不一致（NFR-08）
系统会抛 `ManifestMismatchError` 并提示重建。原则：**不删旧索引硬跑**，先备份再 `--force` 重建：
```powershell
copy-item data\index\scifact data\index\scifact.bak -Recurse
python scripts\build_index.py --scope scifact --force
```

## 4. 里程碑 tag 规范

| tag | 含义 | 触发时机 |
| --- | --- | --- |
| `v0.1.0-scaffold` | 骨架+契约+文档 | W1 设计冻结 |
| `v0.2.0-w2` | 稀疏检索可用 | TF-IDF/BM25 测试通过 |
| `v0.3.0-w3` | 语义检索+公开评价 | SciFact 指标表可信 |
| `v0.4.0-w4` | PDF+RRF | 本地检索链路贯通 |
| `v0.5.0-w5` | 界面+图表 | 四页面可交互 |
| `v1.0.0-final` | 最终提交 | 报告与代码一致、全量测试通过 |

打 tag 命令（Lead 专用）：
```powershell
git tag -a v0.2.0-w2 -m "W2: TF-IDF/BM25 检索可用，测试通过"
git push origin main --tags
```

## 5. 灾难恢复检查清单

- [ ] `.git` 是否存在：`git status`
- [ ] 远端可克隆：`git clone <url> %TEMP%\restore-test`
- [ ] 环境可重建：`tools\setup_env.ps1` 日志无 ERROR
- [ ] 数据可重建：`scripts\download_data.py` + `build_index.py` 成功
- [ ] 测试通过：`python -m pytest -q`
- [ ] 实验可复跑：`run_evaluation.py` 产出的指标与报告一致
